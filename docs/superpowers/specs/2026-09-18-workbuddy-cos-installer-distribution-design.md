# WorkBuddy 安装文件腾讯云分发：简化设计

## 结论

腾讯云只负责保存公开安装文件，GitHub 保留同版本备份。商业后端通过一个环境变量知道腾讯云下载地址，不新增自动上传服务。

## 用户流程

用户仍然只做四件事：创建个人 Key、复制 30 分钟有效的一次性安装提示词、允许 WorkBuddy 执行一次安装、重启后开启 `xiaoye-image` 并检查余额。

## 下载结构

```text
腾讯云 COS（默认）
└─ releases/v1.2.1/三个安装文件

GitHub Release（备用）
└─ v1.2.1/同一批三个安装文件
```

清单记录腾讯云 EXE 地址、GitHub 备用 EXE 地址和 EXE 的 SHA-256。无论从哪个地址下载，安装器都必须通过同一个 SHA-256 校验。

## 后端

新增可选环境变量：

```dotenv
WORKBUDDY_RELEASE_BASE_URL=https://<腾讯云公开下载域名>/releases/v1.2.1
```

未设置时仍使用 GitHub，方便本地开发和回退。设置后，网站签发的提示词使用腾讯云脚本和清单地址；GitHub 地址仍写进提示词和清单供失败回退。

## Windows 安装

- 提示词命令增加 `-ExecutionPolicy Bypass`，只影响本次 PowerShell 进程。
- 安装脚本每个下载地址最多尝试三次，腾讯云失败后使用 GitHub。
- 安装脚本主动移除安装码文件继承权限，只保留当前用户、SYSTEM 和 Administrators。
- 只有退出码为 0 且输出严格等于 `installed` 才算成功。
- 无论成功失败都删除安装码、脚本、清单和 EXE。

## 发布

正式 `1.2.1` 只在 GitHub Actions 构建一次。Release 成功后，把完全相同的三个文件人工上传腾讯云，确保两个下载源的 EXE 具有同一个 SHA-256。本地构建只用于开发验证，不作为正式腾讯云文件。等真实用户安装稳定后，再决定是否增加自动上传、独立下载域名或 CDN。
