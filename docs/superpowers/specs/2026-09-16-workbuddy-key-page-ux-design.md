# WorkBuddy Key 页面体验优化设计

## 目标

让用户创建个人 Key 后立即获得可见、可复制的 WorkBuddy 安装提示词，同时降低页面信息密度。Key 与安装提示词分别展示；完整 JSON 配置和安装器下载入口暂时从 Key 页面移除。

## 创建流程

网站创建 Key 成功后，立即使用新 Key ID 请求一次安装提示词。两个请求保持独立：

1. Key 创建成功后立刻展示并保留；
2. 提示词请求成功后自动展开提示词区域；
3. 提示词请求失败时，Key 不回滚，页面在对应 Key 下显示失败原因与“重新生成”按钮。

这种前端串联方式不改变现有 API 契约，也不把长期 Key 与一次性安装码的创建逻辑耦合到同一个服务端事务。

## Key 条目结构

每个 Key 使用连续账页式条目，不使用悬浮卡片或阴影。条目由三层组成：

### 条目摘要

- Key 名称；
- “有效”状态；
- 最近使用时间；
- 删除操作。

### 个人 Key

- 独立标题“个人 Key”；
- 展示完整 Key；
- 提供“复制 Key”按钮；
- 不与安装提示词或其他配置混排。

### WorkBuddy 安装提示词

- 标题旁显示一次性提示词的有效期；
- 创建 Key 后自动生成并展开；
- 内容使用可选中的代码块展示；
- 提供“复制提示词”和“收起/展开”操作；
- 页面刷新后不持久化或恢复旧提示词，而是显示“生成安装提示词”；
- 提示词过期后停止把它表达为可用内容，显示“已过期”并提供“重新生成”。

## 状态与反馈

- 创建 Key 时按钮显示“正在创建…”；Key 创建成功后立即插入列表。
- 随后的提示词请求显示“正在生成提示词…”，只锁定该 Key 的提示词操作。
- 复制成功在操作区显示“提示词已复制，请粘贴给 WorkBuddy”；复制失败时仍保留完整可选文本。
- 接口失败直接显示服务端安全中文错误，不使用笼统的“服务不可用”覆盖具体原因。
- 删除 Key 后条目立即从列表消失，已生成的提示词随条目一起清除。

## 移除内容

本次从 Key 页面移除：

- WorkBuddy MCP 完整 JSON 配置；
- “复制完整配置”按钮；
- Key 条目内的“下载安装器”入口；
- 关于手动备用配置的说明。

安装引导页可继续保留其独立的手动安装入口，不在本次范围内修改。

## 视觉与响应式

- 延续现有“设计年鉴账页”视觉：暖白纸面、墨色文字、细规则线、方角控件和无阴影层次。
- Key 与提示词用标题、规则线和留白分组，不用大面积淡紫卡片。
- 长 Key 与提示词允许横向滚动或换行，不撑破移动端布局。
- 展开按钮使用真实 `button`，包含 `aria-expanded` 和关联区域，支持键盘操作。
- 提示词状态不仅依靠颜色，同时显示文字标签和有效期。

## 测试范围

- 创建 Key 后自动请求提示词，并在成功后展开。
- 提示词失败时 Key 仍存在且可重试。
- 提示词可展开、收起和重新生成。
- 页面刷新后不显示旧的一次性提示词。
- 完整配置与安装器入口不再出现在 Key 页面。
- 删除 Key 后同时清除对应的提示词 UI 状态。
- 桌面和移动端均不出现横向页面溢出，键盘焦点清晰可见。
