# WorkBuddy 商业平台生产上线清单

此清单是公开注册的发布门禁，不是开发环境的完成声明。每项必须记录执行时间、操作者和证据位置。

## 基础设施

- [ ] 备份旧 SQLite、现有服务器 `.env`、Caddy 配置和当前部署包。
- [ ] 在真实 PostgreSQL 17 上从空库运行迁移两次，第二次无变化且无错误。
- [ ] PostgreSQL 数据卷重启后数据仍存在；每日加密备份已调度。
- [ ] 使用最近一次加密备份完成隔离恢复演练，钱包负数检查结果为 0。
- [ ] COS bucket 为私有；参考图和生成结果生命周期为 24 小时，付款凭证为 180 天。
- [ ] SMTP 验证码和管理员人工复核通知均能送达。

## 身份与账务

- [ ] 管理员邮箱已通过 `BOOTSTRAP_ADMIN_EMAIL` 导入，旧 token 只以摘要保存并通过现有 WorkBuddy 回归。
- [ ] 新邮箱仅获得一次 5 次奖励；重复设备与第 4 个同 IP 账户暂停奖励。
- [ ] 同一订单并发审核只入账一次；两个首次订单并发审核只发一次 10 次奖励。
- [ ] 管理员调账必须填写原因，账本和审计记录可对应。
- [ ] 两个真实测试账户无法互查 Key、余额、任务、订单或付款凭证。

## 生成与故障注入

- [ ] 20 个相同幂等请求只有一个任务、一个 hold 和一次 provider 调用。
- [ ] 真实文生图和多参考图各成功一次，COS 对象、任务状态和 capture 账本一致。
- [ ] 内容限制或参数错误释放冻结，不产生 capture。
- [ ] 在 provider 提交时断网，任务进入 `unknown`，保持冻结且不自动重提。
- [ ] 在 COS 上传后、数据库结算前终止 worker；恢复后通过确定性对象完成一次结算。
- [ ] 在结算后、客户端收到响应前中断；重试返回原任务且不重复扣费。
- [ ] 未知任务超过 24 小时进入人工复核，管理员通知送达。

## 网站与安装器

- [ ] 保存并复核未登录首屏、普通用户主界面和管理员主界面的桌面与 390px 移动截图。
- [ ] 公开 GitHub 仓库已经创建，生产环境设置了 `WORKBUDDY_RELEASE_REPOSITORY=owner/repository`。
- [ ] `v1.2.0` GitHub Actions 成功；Release 中 bootstrap、manifest 和 EXE 三个文件存在、非空且 EXE SHA-256 与 manifest 一致。
- [ ] 在一套无 Node.js 的干净 Windows 环境，从真实用户页面完成“复制安装提示词 → WorkBuddy 请求一次命令权限 → 自动安装 → 开启 `xiaoye-image` → `get_balance` 成功”全流程。
- [ ] 已使用和已过期的安装码均不能再次兑换，并向用户显示可操作的中文下一步。
- [ ] 禁用 WorkBuddy 本机命令执行能力时，不尝试猜测路径，正确展示手动安装器下载入口。
- [ ] 在已有多个 MCP 的配置中安装、修复和卸载，其他 MCP 始终保留。
- [ ] 在损坏配置场景验证备份和恢复路径，记录无法恢复的原始损坏内容。
- [ ] 抽查安装提示词、WorkBuddy 命令参数、安装器输出和服务日志，均不含 `wb_live_` 长期 Key。

首版内测不由以下增强项阻塞：

- [ ] 购买 Windows 代码签名证书，为 EXE 和 bootstrap 增加 Authenticode 签名并验证固定发布者。
- [ ] 扩展 Windows 10/11、默认/自定义配置路径、自定义安装目录和异常环境测试矩阵。

## 安全与观察期

- [ ] `npm test`、`npm run web:build`、`git diff --check` 和依赖审计已复核。
- [ ] 日志抽样不含提示词、完整 Key、图片、付款截图、签名 URL 或 provider 原始敏感响应。
- [ ] `/healthz`、`/readyz`、钱包不变量、未知/人工复核积压和 provider 错误率告警可用。
- [ ] 在关闭公开注册入口的状态下观察至少 48 小时，钱包总额、冻结额、账本和任务状态一致。
- [ ] 产品页面已公开说明扣费、人工充值审核和图片 24 小时有效期；完成以上项目后再开放注册。
- [ ] 生产环境已设置独立 `INSTALLATION_TOKEN_PEPPER`，且未复用 API Key、会话或其他摘要 pepper。
